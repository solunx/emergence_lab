## Planned statistics (only when a candidate exists)

Do not add these to the default `summarize` pipeline until a pattern is actually a candidate. Default reports stay descriptive (means, medians, CIs, paired Δ, histograms). Claiming “this is emergent, not bias” later needs extra tests on the **hits**, written as Python scripts that read `all_metrics.csv` / events of named seeds — not LLM arithmetic.

When that moment comes:

1. **Paired permutation / Wilcoxon** on seed-level Δ, not unpaired t-tests and not Cohen’s *d* on binary survival as a story.
2. **Survival analysis** (Kaplan–Meier or Cox) for time-to-extinction; treat survivors as censored. Binary alive/dead at a fixed tick is a coarse cut.
3. **Bootstrap CI** on the rare-event rate (C2 alive%, any-birth%) — binomial, not normal Cohen’s *d*.
4. **Ablation already in the design:** C1-R vs C2 holds the birth rule fixed. Any emergence claim must survive that contrast, plus C0-R if random walk plus births is the next confound.
5. **Lineage / genome on hits only:** max generation, founder share of births, genome distance from init, whether late descendants still look like C1-greedy in the 9×5 weights. One birth ≠ evolution.
6. **Representability check:** can the C1 greedy policy be expressed (approximately) in C2’s linear genome? If yes, “C2 discovered food-seeking” is a weak claim.
7. **Energy-budget reconstruction** from events on hit seeds (occupancy invariants already exist; a global energy ledger does not).
8. **Multiple-testing hygiene:** pre-register the metric (e.g. persistence of pop>0 past tick 5000 on the same 100 maps) before fishing in outlier GIFs.

Until a candidate appears, do not implement this list. Keep observing.

## Method note — freeze vs fine-tuning

The research question is: **same frozen world, swap the controller.** It is not “search start parameters until C2 looks like life.”

We already moved the economy once (food 20/delay 25 → **30/15**) because a harvest cycle was energy-negative and C2 *could not* reach the birth threshold even in principle. The freeze rule is: tune until reproduction is *possible* (C1-R demonstrated that), then stop. Scanning more seeds, other food values, other mutation rates, or other genome inits to find a universe where C2 persists is a **different experiment** (world sensitivity / fine-tuning), and each change is a new version. Do not do that to rescue C2.

More seeds at 1000 ticks estimate the same 6% flash rate more tightly. They are not new starting physics. Seeds 1–100 already vary map layout and founder genomes; that is the start-position sample we have.

**Genome direction is not yet measured.** BIRTH events log parent/child ids and generation, not weights. Snapshots store genomes of whoever is alive at snapshot ticks (`snapshot_every=100`). Replay currently reconstructs births with `genome=None`. There is no lineage-weight time series in `summarize`. Typical C2 has 0–1 births, so there is no multi-generation trajectory to analyze. Seed 3 reached generation 8 and died at tick 1423 — that flash is the only plausible case study, and only after a lineage actually persists would directional selection vs mutation noise be a fair test.

## 2026-08 — economy patch → **m1-v2**

- **What changed:** `resource_value` 20 → **30**; `regen_delay` 25 → **15**. STAY −1 / MOVE −2 unchanged. Reproduction threshold 150 / parent −75 / child +75 unchanged.
- **Why:** under the v0.2 guess a single-patch harvest cycle was energy-negative. C1 could persist as a small non-reproducing population; C2 could not reach the reproduction threshold on typical maps. That is an economy failure, not a controller result.
- **Rule:** tune until C2 *can* get multiple generations in principle, then freeze. Each later economy change is a new experiment version.
- **Decision after C1-R:** **freeze 30/15**. Do not add food. C2’s 6% survival is bootstrap/lottery, not a dead ecology (C1-R reaches mean max generation ~7 on the same worlds).
